# VideoPilot 前端重构实施计划

## 1. 目标

在不重建后端领域模型、不伪造业务数据的前提下，将当前集中在单一 `JobWorkbench` 中的功能重组为有侧栏、可路由、以当前视频工作区为上下文的 SaaS 界面。

视觉以概念稿为基准：米白和浅灰背景、蓝色主操作、低饱和边框、有限阴影；半透明只用于侧栏、弹框和少量顶层容器，不使用大面积渐变、过度玻璃和无意义悬浮装饰。

本计划只规划实施顺序，不修改运行时代码。M6 的 Agent 能力继续默认关闭，既有效果门失败事实不因界面重构改变。

## 2. 已确认的信息架构

### 2.1 一级导航

1. 视频工作台
2. 媒体资料库
3. 解析任务
4. 视频上下文
5. 证据问答
6. 评测中心
7. 系统设置

侧栏底部保留存储空间和账户入口。未登录时不单独跳转登录页，而是在应用壳层上打开登录弹框。

### 2.2 当前视频工作区

“视频工作区”不是新的后端实体，而是前端对以下既有事实的组合视图：

```text
当前登录用户
  -> AnalysisJob.jobId（路由中的唯一当前上下文）
      -> AnalysisJob.mediaId
          -> MediaAsset
      -> VideoContext
      -> Answers / AgentRun（若实验开关启用）
```

- URL 中的 `jobId` 是当前上下文真源；`mediaId` 从 Job 获取，不维护第二份业务真源。
- 同一视频存在多个 Job 时，默认选择最近的可用 `READY` Job，并允许用户显式切换解析版本。
- “切换视频”弹框展示最近的视频工作区；它负责上下文切换，不代替后端 owner 权限校验。
- 视频工作台、视频上下文和证据问答共享同一个 `jobId`。
- 不新增全局问答历史页；证据问答页只展示当前 Job 的问答。

### 2.3 页面职责

| 页面 | 负责 | 不负责 |
| --- | --- | --- |
| 视频工作台 | 播放、当前视频摘要、内容片段、目标分析摘要、继续问答入口 | 解析运维、全局问答聚合 |
| 媒体资料库 | 上传、媒体列表、选择媒体并发起解析 | 展示 Job 内部阶段 |
| 解析任务 | Job 状态、阶段、事件、取消、恢复/Replay、失败解释 | 媒体上传、问答历史 |
| 视频上下文 | ASR/OCR/关键帧、时间轴、证据定位 | 全局任务统计 |
| 证据问答 | 当前 Job 的问题、答案、引用、拒答/部分回答、实验 Trace | 跨视频聚合历史 |
| 评测中心 | 复用现有 EvaluationWorkbench | 对普通用户伪装为学习统计 |
| 系统设置 | 本地界面偏好、只读系统信息、退出登录 | 展示或修改密钥、绕过服务端配置 |

## 3. 范围分层

### A. 直接复用现有能力（优先交付）

- Session、登录和退出。
- 媒体上传与媒体列表。
- AnalysisJob 列表、详情、SSE、取消和 Replay。
- 视频播放、ASR/OCR/关键帧时间轴。
- 当前 Job 的证据问答、引用跳转、部分回答和 Agent 实验 Trace。
- 评测工作台。

### B. 需要少量新合同（第二阶段）

- 侧栏存储空间：增加 owner-scoped 存储汇总，不能把媒体列表第一页求和冒充总量。
- 播放进度：增加 owner + media/job 绑定的服务端进度；在合同落地前只展示本次会话进度，不宣称跨设备保存。

### C. 不在本次重构中伪造

- 真正的课程章节：当前已有 `VideoSegment`，但没有稳定的 Chapter 领域合同。首版页面使用“内容片段/时间轴”，后续若新增章节生成，应单独立项。
- 完整学习管理系统、掌握度、题库和课程完成率。
- 跨视频问答历史、团队空间、多租户和 Agent 独立工作台。
- 可在网页中修改模型密钥、Provider 或预算硬门的系统设置。

## 4. 路由与状态决策

建议路由：

```text
/workspace/:jobId?       视频工作台
/library                 媒体资料库
/analysis                解析任务列表
/analysis/:jobId         解析任务详情
/context/:jobId?         视频上下文
/answers/:jobId?         证据问答
/evaluation              评测中心
/settings                系统设置
```

- `/workspace`、`/context`、`/answers` 缺少 `jobId` 时展示“选择视频”空状态，不静默读取其他用户或任意任务。
- 选中视频工作区后，在三个上下文页面间切换时保留同一 `jobId`。
- 页面刷新直接根据 URL 恢复；最近打开列表只属于导航偏好，可以按登录用户在浏览器本地保存，并在退出时清除。
- 服务端的 Job、Media、Context、Answer 仍是唯一业务事实；前端不复制状态机。
- 第一阶段使用现有 Job/Media 分页接口组合最近列表；若真实数据量证明产生明显 N+1 或分页错误，再冻结专用查询合同。

## 5. 用户主流程

```text
打开应用
  -> 校验 Session
      -> 未登录：应用壳层 + 登录弹框
      -> 已登录：恢复 URL 中的 jobId
          -> 有效：进入对应页面
          -> 无效/无权限：清除本地最近项并显示可恢复错误
          -> 无 jobId：打开“切换视频”或进入媒体资料库

上传视频
  -> 媒体资料库上传
  -> MediaAsset 探测完成
  -> 填写目标并创建 AnalysisJob
  -> 跳转解析任务详情，订阅 SSE
  -> Job READY
  -> 设为当前视频工作区
  -> 视频工作台 / 上下文 / 证据问答

切换视频
  -> 打开最近视频工作区弹框
  -> 按 Media 分组显示最近 Job
  -> 默认使用最近 READY Job；运行中 Job 标明暂不可问答
  -> 更新路由 jobId
  -> 三个上下文页面同步切换

证据问答
  -> 当前 jobId 加载问答历史
  -> 提问
  -> ANSWERED / PARTIALLY_ANSWERED / REFUSED
  -> 点击引用跳到当前视频时间点
  -> Agent 未晋级时实验入口仍默认隐藏/关闭
```

## 6. 依赖图与实施顺序

```text
F0 冻结页面/路由/视觉验收合同
  -> F1 应用壳层、设计令牌与 Router
      -> F2 登录弹框和账户菜单
      -> F3 当前视频工作区与切换器
          -> F4 媒体资料库页
          -> F5 解析任务页
          -> F6 视频上下文页
          -> F7 证据问答页
          -> F8 视频工作台聚合页
              -> F9 存储空间真实汇总
              -> F10 最小播放进度
          -> F11 评测中心与系统设置
              -> F12 响应式、可访问性和全链路回归
```

F4-F7 在 F3 合同稳定后可分别实施，但共享组件和路由参数不得并行修改。F9、F10 是独立后端纵切，不阻塞核心界面重构。

## 7. 关键实现原则

- 优先拆分现有组件而不是重写业务逻辑；迁移期间每个提交都保持 `npm run check` 可通过。
- 页面组件只编排 feature，不直接拼接 API URL；继续使用版本化 API client。
- Controller 仍只调用 application service；新增存储/进度合同必须 owner-scoped。
- 不使用假存储容量、假课程章节、假学习完成率或假解析进度。
- 不把 `MediaAsset READY` 当成 `AnalysisJob READY`；问答入口必须以后者为准。
- 桌面侧栏在窄屏变为可关闭抽屉；320px 下不保留压缩到不可读的固定栏。
- 登录弹框必须有焦点圈定、Esc/关闭规则、错误提示和提交中状态；未登录时底层业务控件不可操作。
- 颜色、阴影、圆角、间距和排版由 CSS 令牌统一管理；不在页面散落魔法值。

## 8. 检查点

### Checkpoint A：壳层与上下文（F0-F3）

- 刷新后由 URL 恢复同一 Job。
- 未登录只出现登录弹框，登录后不创建第二个 Session 边界。
- 切换视频后工作台、上下文和问答使用相同 `jobId`。
- 越权或已删除的最近项不会显示旧数据。

### Checkpoint B：核心页面迁移（F4-F8）

- 上传 -> 创建 Job -> SSE 进度 -> READY -> 播放 -> 问答 -> 引用跳转完整可用。
- 解析任务与问答历史职责分离。
- 原有取消、Replay、降级上下文、部分回答和拒答状态均未丢失。
- Agent 默认关闭事实和 Trace 脱敏边界不变。

### Checkpoint C：真实辅助数据（F9-F11）

- 存储用量来自 owner-scoped 服务端聚合。
- 播放进度刷新后可恢复，且不能跨 owner 读取。
- 设置页不暴露密钥，不修改后端质量门。

### Checkpoint D：完整交付（F12）

- `client\npm.cmd run check` 通过。
- 涉及后端时 `server\mvnw.cmd test` 通过；合并前执行 `verify -Pintegration`。
- 320px、768px、1440px 真实浏览器验收通过，Console 无错误，关键网络请求符合合同。
- 键盘主路径、焦点可见、弹框焦点管理和 WCAG AA 对比度通过。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 页面拆分时复制请求和状态 | 同一 Job 出现不同事实 | 路由 `jobId` 为唯一上下文，业务请求保留在 feature/API client |
| 最近列表把 Media 与 Job 混淆 | 上传完成但无法问答 | 明确区分 Media READY 与 Job READY，并显示解析版本 |
| 视觉重构破坏既有功能 | 回归取消、Replay、引用跳转 | 按页面纵切迁移，先保留测试再调整结构 |
| 存储/进度没有后端合同 | UI 出现假数据 | F9/F10 独立实现，合同完成前显示真实空状态 |
| M6 实验入口被误认为已发布 | 违反当前质量门 | 沿用 feature flag 和默认关闭，不新增一级 Agent 导航 |
| 组件拆分范围过大 | 单次变更难验证 | 每项控制在 S/M，超过约 5 个生产文件时继续拆分 |

## 10. 计划边界

本计划不替代 `tasks/M6/TODO.md`，也不将 M6 标记为退出。实际实施前应由负责人确认本计划，然后严格按 `TODO.md` 的单项任务和检查点推进；未经确认不开始运行时代码修改。
