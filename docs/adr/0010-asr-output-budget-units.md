# ADR-0010：ASR 输出按字符计量并设置时长相关硬门

## Status

Accepted

## Date

2026-11-09

## Context

`m4-limits-v1` 将 ASR 音频时长毫秒同时写入 `model_call.input_units` 和
`output_units`。两个 60 秒分片会累计 120000 输出单位并超过 Job 的 100000
兜底上限，因此正常的长视频会被错误终止。若只把输出改为字符数但仍仅依赖
100000 的 Job 总门，单个短音频的异常超长响应又无法及时被拦截。

ASR 默认每 60 秒切片调用一次。正常普通话 120 秒通常只有数百个汉字；英语
转写按常见语速和空格、标点计算通常也远低于 2400 个 Unicode 字符。阈值需
容纳语言和语速差异，同时在供应商返回重复文本或异常膨胀时立即失败。

## Decision

执行限制版本升级为 `m4-limits-v2`，历史 v1 Trace 和失败记录不改写。

- ASR `input_units` 继续记录受信音频窗口的毫秒数，用于输入规模和调用预算。
- ASR `output_units` 记录持久化转录文本的 Unicode code point 数，不再重复记录时长。
- 每次 ASR 响应还必须满足 `ceil(durationMs * 1200 / 60000)` 字符上限；默认
  60 秒最多 1200 字符，120 秒音频经两个标准分片合计最多 2400 字符。
- 超出单次上限视为供应商非重试型 `OUTPUT_LIMIT`，保留调用和失败审计，不自动
  产生第二次付费调用。
- Job 的 100000 总输出单位门保持不变，作为跨 ASR、OCR 和生成模型的保守兜底，
  不把它解释为单段 ASR 的许可量。

1200 字符/分钟是 MVP 的宽容安全上限，不是内容质量目标。后续若有冻结评测证明
其他语言或专业语速需要调整，必须提升限制版本并保留旧报告的版本指纹。

## Alternatives Considered

- 保持时长作为输出单位并提高 100000：仍然重复计量，而且会继续随视频时长误杀。
- 只改成字符数、保留单一总门：120 秒可返回近 100000 字符，无法及时阻止异常响应。
- 使用响应字节数：同一文本在不同 UTF-8 字符组成下不可比，也不贴近可消费文本量。
- 为本次素材缩短视频：绕开了生产预算缺陷，并降低发布数据集的内容覆盖。

## Consequences

- 正常长视频不再因 ASR 时长被重复计入输出而失败。
- 单次异常膨胀响应在写入转录产物前被确定性拒绝。
- 运维和评测比较预算时必须包含 `limitsVersion`；v1 与 v2 的 ASR 输出单位不可直接比较。
- 100000 总门仍混合各 Adapter 报告的标准化输出量，因此只用于安全兜底；供应商成本
  继续以独立价格和费用字段为准。

## Validation

- 单元测试证明实际文本字符数进入 ASR 完成记录，并证明时长相关上限拒绝异常输出。
- MySQL 集成测试证明 `model_call.output_units` 保存字符数而非供应商计费时长。
- 使用两条中文教学视频执行真实 TeleSpeechASR，确认多分片解析不会在 120 秒处误触发
  `BUDGET_OUTPUT_UNITS`，且每条调用仍保留输入时长、字符输出和限制版本审计。
